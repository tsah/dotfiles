# Local worktree workflow

## Architecture

Worktrunk is authoritative for worktree creation, setup hooks, switching, and destruction. Stock `wt` remains the native Worktrunk executable: this repository intentionally provides no `bin/wt`, compatibility wrapper, or parallel worktree manager. `wayfinder/src/workflow.ts` invokes native Worktrunk and adds only tmux and local agent orchestration; `bin/dotfiles-workflow` is its stable shell boundary.

A workspace is identified by its canonical worktree path. Repository identity comes from `git rev-parse --git-common-dir`. Tmux session names are display labels (`repo@branch`) with an eight-character path hash only when that label collides. The canonical path and common dir are recorded as tmux user options. Session lookup scans those canonical path tags before generating a name, so renaming a session with tmux does not detach its agents or cause orchestration to create a duplicate canonical session. Legacy untagged sessions are adopted by canonical `session_path` and tagged on first use. Never use a tmux name as identity.

Workspace lineage is dynamic parent-child metadata rather than fixed orchestrator/worker roles. Any workspace with children is derived as an orchestrator, and nested workers naturally form chains such as `A → B → C`. The authoritative operational store lives in SQLite at `$XDG_STATE_HOME/alt-k-tui/workspaces.sqlite3` (falling back to `~/.local/state/alt-k-tui/workspaces.sqlite3`) via `bun:sqlite`, with WAL, `foreign_keys`, `busy_timeout`, and `PRAGMA user_version` migrations. Every active worktree also gets an ignored projection at `.alt-k/workspace.json` containing the durable workspace and repository IDs, canonical path, common dir, branch, parent ID, revision, and timestamps. SQLite remains authoritative during normal operation; `dotfiles-workflow workspace bootstrap` can reconstruct an empty store from manifests, and `dotfiles-workflow workspace reconcile` regenerates manifests from the database.

Manifest writes are atomic and local-only. The workflow adds the exact `/.alt-k/workspace.json` rule to that worktree's `.git/info/exclude`, and it refuses to overwrite tracked, symlinked, symlink-parented, malformed, or foreign conflicting files. Only genuinely ephemeral PID, Unix-socket, and agent-report files remain in `$XDG_RUNTIME_DIR`.

Sessions are created lazily. Their stable `main` window is retained; every visible agent gets a dedicated, uniquely named window that remains available for follow-up after the agent settles. `worker-pi`, `worker-claude`, and `worker-opencode` are thin harness adapters. `agent-*` starts another visible agent in the current worktree. OpenCode is not filesystem-sandboxed. Repository agent configuration takes precedence over personal configuration through each harness's native lookup. Worktree sessions mirror their durable workspace ID and current parent workspace ID into tmux user options alongside the canonical path/common-dir tags.

`worker-*` captures the caller's current workspace before invoking Worktrunk, then best-effort links the new child worktree back to that parent. `agent-*` and Waystation's branch picker never add lineage edges. `worker-* --no-parent` forces a root workspace, while `worker-* --parent WORKSPACE_ID` explicitly reuses a recorded parent and fails if that ID is unknown. `DOTFILES_WORKSPACE_LINEAGE=off|best-effort|strict` controls persistence behavior: `best-effort` is the default and preserves existing workflows even if the store or manifests cannot be updated, `off` disables lineage persistence entirely and rejects explicit `--parent` requests, and `strict` turns persistence failures into command failures.

Normal Pi delegation uses the pinned `@tintinweb/pi-subagents` package. Its `Agent`, `get_subagent_result`, and `steer_subagent` tools run child sessions in the parent Pi process, subject to `pi/subagents.json`; they do not create tmux windows and do not appear in Waystation. Its native `isolation: worktree` mode bypasses Worktrunk, so use `worker-pi` instead whenever a task needs an isolated handoff or visible session.

Waystation is the shared entrypoint. Bare `waystation` remains the interactive navigator (`workspace-picker` is retained as a compatibility launcher, and shell function `s` opens it), while `waystation agent list|status|capabilities|wait|send|result` is its stable headless agent API. Open the TUI with `Alt-K`. It combines tmux sessions, worktrees/configured directories, git state, agent state, and workspace lineage. Its jump screen is a bottom-sorted selectable tree with blocked/working live sessions nearest the prompt, followed by ready sessions, idle sessions, neutral/unknown sessions, sessionless worktrees, and finally plain directories; recency and frecency order rows only within those priority groups. Session-to-session lineage uses real recursive connectors, root rows place their color-coded aggregate-state glyph before the disclosure marker while nested sessions place it immediately after the `├─`/`└─` child connector, and collapsed window/agent names are summarized inline immediately after the owning session name without right-edge status glyphs. Small lineage subtrees with one to three direct child sessions begin expanded; larger ones also begin expanded when they contain a working or ready agent, and otherwise begin collapsed. Explicit detail expansion renders subdued bullet rows beneath the owning session without competing with lineage connectors. Session, picker, active-pane, and agent events persist canonical-path activity under `XDG_STATE_HOME`; after cache, tmux-server, or machine restart, sessionless directories sort by the newest durable event, dirty-file mtime, worktree reflog, or commit, with zoxide frecency as a final tie-breaker. Directory rows display the winning source and age, and expensive Git recovery evidence refreshes at most once per minute. Lineage metadata still contributes hidden search labels, and a collapsed lineage parent may show a small child count when useful. The picker reads lineage in fail-open mode by default so a broken lineage database hides annotations rather than breaking navigation; strict administrative lineage commands still fail. Right first exposes hidden lineage children for the selected session, then expands its exact detail rows. Left on a detail jumps to its owning session, then collapses exact detail rows before collapsing lineage children and finally jumping to the lineage parent. Filtering preserves the full ancestor context for matching descendants even when their ancestors were collapsed, but non-empty queries show only directly matching detail rows instead of leaking every expanded detail. Typing or pasting preserves the selected row when it still matches; otherwise the picker selects the best direct match for the new query. Cache refreshes are authoritative for membership and ordering, then restore selection by stable row identity when possible. When opened from tmux, the current session row is initially selected. Enter jumps to the selected session, window, agent, worktree, or directory, and Enter on zero matches leaves the picker open. Agent state is normalized as `blocked`, `working`, `done`, `idle`, or `unknown` and displayed as color-coded `waiting`, `working`, `ready`, `idle`, or `unknown`; a completion remains ready until that target is focused, then becomes idle, while a newer completion becomes ready again. Alt-D asks for y/n confirmation and destroys an exact selected child pane; if that pane is the session's last pane, it destroys the session and its linked worktree instead. Destruction completes before the picker closes, and a failed tmux or Worktrunk command leaves the picker open with its error instead of silently returning to the stale target. Alt-R renames any selected tmux session row by stable session ID while leaving canonical path metadata, lineage metadata, and included agents unchanged. Alt-A opens a searchable list of valid same-repository parent workspaces for the selected direct workspace row; descendants, the workspace itself, and its current parent are excluded, and Enter reparents the selected workspace with its subtree intact. Alt-L detaches any selected direct workspace row from its parent, making that workspace and its existing descendants a top-level subtree while preserving the workspace, session, and worktree. Both lineage actions update the authoritative store, manifest projection, and tmux mirror. Pressing Alt-K again while the picker is open begins the explicit repository picker, then presents existing worktrees, local branches, and remote branches together. Selecting a repository renders cached refs immediately while `git fetch --all --prune` refreshes them in the background; remote rows are sorted by commit recency. Text input and bracketed paste both work in search and branch/base fields. Typing a name without an exact branch match offers to create that branch and prompts for its base. The flow delegates worktree creation and switching to native Worktrunk, then lazily ensures the tmux session. Alt-B opens the same UI at the repository step. Worktree creation/destruction remains delegated to native Worktrunk so its setup and confirmation behavior remains authoritative.

Every discovered agent pane has an opaque generated ID such as `ws-…`, stored in the pane-scoped tmux option `@waystation_agent_id`. IDs survive session renames and agent turns and are the only mutation/wait selectors exposed by the headless API; pane IDs remain compatibility/discovery metadata. Tmux is used only to discover panes and read or write agent/session metadata. Waystation never communicates with an agent through `send-keys`, `load-buffer`, `paste-buffer`, or `capture-pane`.

The globally installed Pi lifecycle extension serves a mode-`0600`, per-process Unix socket under `$XDG_RUNTIME_DIR/alt-k-tui-$UID/agent-sockets/`, advertises that socket through pane metadata, and handles sends with Pi's native `pi.sendUserMessage`. An idle send starts immediately; a busy send defaults to `followUp`, while callers may request `steer` or `follow-up`. The extension records monotonically increasing lifecycle generations, the latest settled generation, and the last 20 assistant results in the per-pane report. `agent_settled`, not `agent_end`, advances settlement, so `wait --after N` and `result --generation N` work across multiple turns without closing the agent window. A timeout reports failure and leaves the pane/worktree running.

Pi supports `status`, report-based `wait`, native `send`, and structured `result` fully. The Pi endpoint accepts only one unsettled external message at a time so the returned generation baseline remains correlated with its result. Claude and Codex panes can be listed, inspected, and waited on through lifecycle hook reports; their unverified native `send`/`result` capabilities return explicit unsupported errors. OpenCode is monitor-only: wait and HTTP mutation remain disabled until its local contract is verified. `capabilities` reports these distinctions rather than allowing a tmux-input fallback.

The Linux `wayfinder-resource-guard` user service monitors guest-kernel memory PSI together with `MemAvailable`. Sustained pressure can terminate at most one fully validated, non-focused Pi, Claude, or OpenCode process per boot, preferring settled agents before working agents. It persists termination incidents and boot-ID snapshots under `$XDG_STATE_HOME/alt-k-tui`; Wayfinder renders terminations and agents lost across an unclean reboot as red `×` incident details. EC2 uses the same guest `/proc` signals, with a larger default reserve for swapless instances. Orderly service shutdowns do not produce reboot-loss incidents.

Workflow `--wait` uses the same report generations instead of one-shot signal files. `dotfiles-workflow send` is retained as a compatibility boundary, but resolves its pane or stable ID to the native Waystation transport and rejects `--no-submit`. Neovim considers only agents in the canonical current worktree, remembers the stable agent ID, and sends through `waystation agent send`; `AgentAppendContext` sends a submitted native follow-up because native APIs do not expose an unsubmitted editor buffer.

## Milestones and acceptance criteria

1. **Identity and orchestration:** canonical path/common-dir identity; lazy collision-safe session; stable main window; multiple agent windows; thin harness adapters; native `wt switch --create` setup.
2. **One navigation surface:** Waystation (`Alt-K` and `s`) displays sessions, configured/zoxide directories, git and agent status; no legacy switcher or remote-worker process remains.
3. **Editor and agent lifecycle:** stable pane-scoped agent IDs; headless Waystation agent API; native Pi Unix-socket send/result; report-generation waits; unified `Agent*` commands with current-worktree filtering and explicit unsaved-buffer choice; verified self-destruction boundary.
4. **Distribution:** one desktop/server manifest, pinned Pi subagent package installation, only ledger-owned stale links reconciled, neutral skills under `skills/`, obsolete entrypoints absent.

Practical inspection and repair commands live behind `dotfiles-workflow workspace show|tree|project|reconcile|bootstrap`.
